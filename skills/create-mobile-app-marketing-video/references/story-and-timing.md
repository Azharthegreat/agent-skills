# Story and Timing

## Short-form structure

| Segment | Typical time | Purpose |
| --- | ---: | --- |
| Hook | 0–2 s | Show the problem or strongest result immediately |
| Product reveal | 2–5 s | Identify the app and central promise |
| Feature proof | 5–18 s | Demonstrate two to four features with real UI |
| Trust or privacy | 18–23 s | State one verified differentiator |
| CTA | Final 3–5 s | Show one clear action and store destination |

Match each claim to visible UI evidence. Shorten pauses in recordings while leaving enough time to understand taps and state changes.

## Shot manifest

Record for every scene: start time, duration, source file, crop, visible feature, on-screen text, narration line, caption line, transition, sound cue, and destination aspect ratio.

Create language-neutral visuals when possible so Urdu and English versions can share the same master timeline.

## Hooks

Prefer concrete user moments: lending a phone, protecting one private photo, stopping unauthorized app access, saving time, or demonstrating a visible creative result. Avoid vague claims such as "the future is here".
